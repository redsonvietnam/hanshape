# HanShape Adaptive Matcher\n\n## Goal\n\nGiven the current candidate set, automatically choose the next visual question that is expected to reduce the candidate set efficiently.\n\nHanShape now supports both:\n\n- **greedy search** (`lookaheadDepth: 1`)\n- **multi-step lookahead** (`lookaheadDepth: 2`, `3`, ...)\n\nThe adaptive matcher remains a search layer on top of the semantic matcher.\n\n## Search model\n\n```\ncandidate set\n   ↓\ngenerate observable predicates\n   ↓\npartition candidates into YES / NO\n   ↓\nmeasure information gain\n   ↓\naccount for recognition cost\n   ↓\noptionally evaluate future branches\n   ↓\nchoose next question\n```\n\nA candidate set is the state. After every answer, the engine recomputes the next question from the new candidate set.\n\n## Information gain\n\nFor a binary question with `n` candidates:\n\n```\np = YES / n\n\nH(p) = -p log2(p) - (1-p) log2(1-p)\n```\n\n`H(p)` is the immediate information gain.\n\nFor `lookaheadDepth: 1`, the score is:\n\n```\nscore = informationGain / recognitionCost\n```\n\nThis preserves the original v0.7 greedy behavior.\n\n## Multi-step lookahead\n\nFor depth greater than 1, HanShape recursively evaluates the best conditional question in each future branch.\n\nThe score becomes:\n\n```\nexpectedInformationGain / expectedCost\n```\n\nwhere:\n\n```\nexpectedInformationGain\n  = currentInformationGain\n  + P(YES) * futureYESInformationGain\n  + P(NO)  * futureNOInformationGain\n\nexpectedCost\n  = currentCost\n  + P(YES) * futureYESCost\n  + P(NO)  * futureNOCost\n```\n\nThe engine therefore does not only maximize the immediate split. It can prefer a question whose child candidate sets are easier to resolve on the next step.\n\nThe cumulative expected information gain is bounded by the entropy of the current candidate distribution:\n\n```\nexpectedInformationGain <= log2(candidateCount)\n```\n\nfor the uniform candidate model used by the prototype.\n\n## Example\n\nStart with:\n\n```\nSINGLE + 3 strokes\n→ 大 / 土 / 士\n```\n\nA greedy search only evaluates the next split.\n\nWith:\n\n```js\nchooseNextQuestion(candidates, { lookaheadDepth: 2 })\n```\n\nthe engine also evaluates what the best second question would be inside each YES/NO branch.\n\nThe engine does not need a special rule such as:\n\n```\n大/土/士 must ask X, then Y\n```\n\nInstead, the same semantic ontology and matcher are recursively reused.\n\n## Returned metadata\n\nAdaptive questions expose the immediate metrics:\n\n```\ninformationGain\nexpectedRemaining\neliminationRatio\nscore\n```\n\nand the lookahead metrics:\n\n```\nlookaheadDepth\nexpectedInformationGain\nexpectedCost\nlookaheadScore\n```\n\nWith depth 1:\n\n```\nexpectedInformationGain == informationGain\nexpectedCost == cost\nlookaheadScore == score\n```\n\n## Question sources\n\nThe generator derives questions only from the current semantic character model:\n\n- topology: enclosure, connectivity, crossing\n- geometry: axis, curvature, symmetry, convergence\n- stroke type: presence of dot/hook/etc.\n- boundary contact\n- junction thresholds\n- semantic relations such as relativeLength and relativePosition\n\nNo new digit is required.\n\n## Architectural rule\n\nThe adaptive layer does **not** replace the matcher.\n\n```\nabstract query\n      ↓\n   matcher\n      ↓\ncandidate set\n      ↓\nadaptive question selector\n      ↓\nnew abstract query\n      ↓\nmatcher\n```\n\nThe matcher remains deterministic. The adaptive layer decides what to ask next.\n\nThe adaptive engine also remains independent from numeric digit bindings.\n\n## Current limitation\n\nThe lookahead currently assumes:\n\n- candidates are equally likely\n- recognition cost is manually assigned\n- questions are binary\n- future branches use the same observable-question generator\n- the search is bounded by the requested lookahead depth\n\nBenchmark status:\n\nOn the current 19-character semantic corpus, the six adversarial groups are solved in 19/19 cases with an average of 1.789 questions and a maximum of 3. Exhaustive 4-character subset benchmarking across 3,876 subsets and 15,504 target cases found that depth-2 lookahead reduced average questions only slightly (about 0.12% versus greedy depth 1), while some cases became worse. Therefore greedy depth 1 remains the default; lookahead is experimental and should stay opt-in until larger, more realistic corpora justify its complexity.\n\nRecognition cost:\n\nThe matcher supports `costMode: "flat"` and `costMode: "weighted"`. Flat mode is the default because the current numeric costs are provisional and have not been calibrated from user observations. Weighted mode remains available for experiments.\n\nThe next useful research steps are:\n\n- user-specific recognition costs\n- learned question difficulty from real interactions\n- non-uniform candidate priors\n- uncertainty/confidence\n- negative query representation\n- adaptive digit assignment\n## Current benchmark findingsOn the current 19-character semantic model:- the six adversarial groups solve 19/19 target cases;- average questions are 1.789 and maximum depth is 3;- all 171 character pairs are separable by at least one current discriminator;- 10 pairs are fragile because all available discriminators belong to only one concept: relativeLength, strokeType, or boundaryContact;- with flat recognition cost, the deterministic sample benchmark found no average improvement from depth 2 over depth 1; lookahead remains an experimental option rather than the default strategy.The implication is that the next major research bottleneck is **corpus coverage and human recognition data**, not more search depth.
